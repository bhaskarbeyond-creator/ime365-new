## E. Current implementation

Basic entitlement declares `allowsAllTemplates:false`, but no consumer was found. Admin saves PRO/disabled arrays. Landing filters/labels some cards but selection gates authentication only; builders enumerate all; saves accept IDs; PDF/DOCX check global export entitlement, not per-template policy.

## F. Reproduction evidence

Configure one template disabled/PRO, then trace or test picker, direct builder URL/state, save and export. The server paths do not resolve per-template policy. Disabled direct use is unconditional; PRO impact depends on configured subscription mode.

## G. Expected behavior

One server-authoritative policy determines template existence/status/entitlement for select, save, reopen, publish, preview, PDF, DOCX and print. UI mirrors decisions but is not the boundary.

## H. Root cause analysis

Template configuration was implemented as frontend metadata in separate bundles while backend entitlement checks remain global → policy drift and bypass.

## I. Detailed technical solution

- Create canonical catalog with kind, status (`free/pro/disabled`), version and allowed entitlements.
- Expose a sanitized public catalog and evaluate policy server-side in a shared service.
- Call it from resume/cover save, publication, preview, PDF and DOCX; preserve grandfathering rule explicitly.
- Make states mutually exclusive and reject overlap.
- Have UI render server decisions/reasons and fail closed on stale configuration.

## J. Proposed patch / code-level repair

```js
const decision = await templatePolicy.authorize({
  templateId: req.body.templateId,
  documentKind: 'resume',
  entitlement: req.entitlement,
  action: 'save',
});
if (!decision.allowed) return res.status(decision.status).json({ code: decision.code });
```
