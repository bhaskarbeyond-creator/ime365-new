## E. Current implementation

The active `covers` chunk exports only named `getCovers`. Listing imports it correctly; save/delete dynamically import a nonexistent default and call `.saveCover()`/`.deleteCover()`. UI expects `result.id` while create returns `result.cover.id`. UI sends `templateId`; repository reads `data.template`, defaulting to Cover1.

## F. Reproduction evidence

Direct Node ES import reports keys `[getCovers]`. Trace active callers: create/edit/duplicate/delete use wrappers that dereference undefined default before HTTP. Backend CRUD is mounted and present.

## G. Expected behavior

One typed/named cover API exposes list, create/update and delete; request/response/template fields match backend contracts and Cover1–4 round-trip.

## H. Root cause analysis

Lazy chunk was reduced to one named export while facade retained an older default-object contract; response and template field names also drifted independently.

## I. Detailed technical solution

- Restore frontend source first; do not edit minified output.
- Export/import explicit named functions (`getCovers`, `saveCover`, `deleteCover`).
- Normalize create/update response to one documented `{success, cover:{id,...}}` or facade adapter.
- Choose `templateId` as canonical API/storage field (or consistently map to existing `template`) and migrate existing rows safely.
- Add compile-time/type and production-bundle symbol-contract tests.

## J. Proposed patch / code-level repair

```js
// covers source module
export const getCovers = () => client('/api/covers');
export const saveCover = (id, cover) => client(`/api/covers/${id}`, { method: 'PUT', body: cover });
export const deleteCover = id => client(`/api/covers/${id}`, { method: 'DELETE' });

// facade
const { saveCover } = await import('./covers');
const result = await saveCover(payload.id, { ...payload, templateId: payload.templateId });
return { ...result, id: result.cover?.id };
```
