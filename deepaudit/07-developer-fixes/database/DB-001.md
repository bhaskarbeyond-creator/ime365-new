# A. DB-001 — Readiness ignores schema state and races asynchronous bootstrap

## B. Severity

P1 — High. A connected database with pending, mismatched or failed migrations can receive production traffic.

## C. Confirmation status

**CONFIRMED BY SOURCE AND RUNTIME**

## D. Affected code locations

- [`backend/index.js:4212-4255`](https://github.com/bhaskarbeyond-creator/ime365-new/blob/df5902dd897ff8e7955a738ac580f2a0d0263d0d/backend/index.js#L4212-L4255)
- [`backend/index.js:4260-4268`](https://github.com/bhaskarbeyond-creator/ime365-new/blob/df5902dd897ff8e7955a738ac580f2a0d0263d0d/backend/index.js#L4260-L4268)

## E. Current implementation

The readiness predicate is `mysql.connected === true` even though the payload reports schema incompleteness. Startup invokes bootstrap without awaiting it. In the isolated unavailable-DB run, readiness correctly returned 503, but source proves a connected invalid schema can be green.

## F. Reproduction evidence

Read the predicate and bootstrap ordering. Simulate a repository with `connected=true` and schema state `NOT_RUN`/failed; the current predicate remains true.

## G. Expected behavior

Liveness reflects process life only. Readiness becomes true only after required dependencies and the exact authoritative schema are verified current; failed bootstrap remains alive but unready.

## H. Root cause analysis

Connection health and schema compatibility are modeled separately but only connection participates in the ready decision; bootstrap lifecycle is not joined to listener/readiness state.

## I. Detailed technical solution

- Create explicit startup states: STARTING, MIGRATING, READY, FAILED.
- Await/track schema bootstrap before opening readiness; migrations should run under one authority/lock.
- Compute readiness from connection, schema checksum/version and required service state.
- Return a stable public status; expose details only internally per SEC-006.

## J. Proposed patch / code-level repair

```diff
-const ready = mysql.connected === true;
+const ready = mysql.connected === true
+  && bootstrapState.status === 'READY'
+  && schemaState.current === true;
```
Startup stores the bootstrap promise/result and never treats `NOT_RUN`, pending, mismatch or failure as ready.

**Patch verification:** SOURCE-REVIEWED ONLY; disposable MariaDB integration test required.
