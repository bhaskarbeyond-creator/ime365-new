## E. Current implementation

Checked migrations define 66 unique tables, `schema.sql` 64, and the tracked live dump 79. FirestoreRepository, sync manager, fencing and tombstone code remain while runtime comments describe MariaDB-only authority.

## F. Reproduction evidence

Hash and table-name compare the three SQL sources, then search imports/references for retained dual-store modules. Counts and hashes differ.

## G. Expected behavior

Ordered migrations are authoritative; schema snapshots are generated from them. Every retained data-plane module has an active owner/use case or is safely removed.

## H. Root cause analysis

Multiple hand-maintained schema/data-authority artifacts → independent drift → ambiguous bootstrap, restore and failover behavior.

## I. Detailed technical solution

- Declare migrations the sole source of truth in an ADR.
- Generate schema snapshots from a clean migrated database; never hand-edit them.
- Inventory runtime references and operational dependencies for Firestore/sync/fencing/tombstones.
- Characterize backup/restore/failover behavior before removing anything.
- Add checksum and table-set comparison to CI.

## J. Proposed patch / code-level repair

```text
backend/database/migrations/*.sql  -> authoritative
CI disposable MariaDB              -> generated schema snapshot/checksum
Firestore/sync modules              -> retained only with documented active owner and tests
```

**Patch verification:** DESIGN ONLY; no schema or module removal was performed.

## K. Step-by-step developer implementation

1. Approve authority ADR.
1. Build clean migration fixture.
1. Generate/compare schema snapshot.
1. Trace and test dual-store references.
1. Remove only proven-retired modules in small commits.
1. Run restore and rollback drills.

## M. Regression analysis

Removing an apparently dormant failover path can destroy recovery capability; require operational owner sign-off.

## N. Exact test cases

- DB-003-T1 — empty database migrates to expected checksum/table set.
- DB-003-T2 — generated snapshot equals migration result.
- DB-003-T3 — reference/runtime trace proves each removal unused.
- DB-003-T4 — backup restore succeeds without retired modules.

## O. Acceptance criteria

- One documented schema authority.
- CI detects any snapshot/migration divergence.
- No unexplained dump-only production table.
- Every retained data-plane module has owner and tests.

## P. Rollback plan

Restore a removed module only from the same immutable revision with its characterization tests; never restore the data dump.
