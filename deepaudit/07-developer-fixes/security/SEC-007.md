# A. SEC-007 — users.read permission grants complete private-user export

## B. Severity

P2 — Medium. Support and auditor roles can retrieve substantially more personal data than directory-read duties require.

## E. Current implementation

SUPPORT and AUDITOR receive `users.read`. The export route accepts `users.read` as fallback to `users.export` and returns identity/MFA metadata, profile, resumes, cover letters, favourites, notifications, applications and billing orders.

## F. Reproduction evidence

Evaluate role grants and route fallback. A SUPPORT/AUDITOR token satisfies export authorization without a distinct export capability.

## G. Expected behavior

Directory reads are field-minimized. Full export requires explicit `users.export`, recent privileged authentication, purpose/justification, target notification policy and immutable audit.

## H. Root cause analysis

Broad read permission was reused as an export authorization → least-privilege boundary collapses between lookup and bulk sensitive-data extraction.

## I. Detailed technical solution

- Remove `users.read` fallback and define `users.export` only for approved role(s).
- Require recent MFA step-up and reason/ticket identifier.
- Return role-specific projections; minimize identity/security/billing fields.
- Audit requester, target, purpose, field set and result without sensitive contents.
- Add rate limits and anomaly alerts.

## J. Proposed patch / code-level repair

```diff
-if (!has('users.export') && !has('users.read')) deny();
+requirePermission('users.export');
+requireRecentAdminAuthentication(req);
+requireExportPurpose(req.body.reason, req.body.ticketId);
```
