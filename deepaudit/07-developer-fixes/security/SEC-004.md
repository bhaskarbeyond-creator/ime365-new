# A. SEC-004 — API proxy transport and trusted-client-IP controls are inconsistent

## B. Severity

P1 — High. Checked code can forward bearer tokens and resume/admin bodies over cleartext to a public-routable address; IP attribution/rate limiting can collapse behind an untrusted proxy. External reachability is topology-dependent.

## E. Current implementation

PHP hard-codes an `http://` IP upstream and forwards authorization headers/body. Node HTTP fallback binds all interfaces. Node trusts only loopback by default while PHP sets forwarding headers. Global rate limiting runs before authentication, so its UID fallback cannot be populated.

## F. Reproduction evidence

Inspect configuration/order. In staging, capture hop encryption/bind/firewall and compare `req.ip` through the actual proxy. The audit intentionally did not contact the hard-coded upstream.

## G. Expected behavior

Gateway uses loopback/Unix socket when colocated or mutually authenticated TLS when remote; backend is not directly reachable; exact proxy addresses are trusted; authenticated limits key by UID after auth.

## H. Root cause analysis

Gateway, backend bind, trust-proxy and limiter were configured independently → transport and identity assumptions do not line up.

## I. Detailed technical solution

- Move upstream to environment/server config and validate scheme/host.
- Prefer loopback/Unix socket and bind Node to loopback; otherwise mTLS HTTPS and firewall allowlist.
- Configure Express trust proxy to exact proxy addresses/CIDRs, never broad hop count without topology proof.
- Keep coarse pre-auth IP limit; add post-auth UID/account limit after authentication.
- Add forwarded-header spoof tests and secure operational documentation.

## J. Proposed patch / code-level repair

```diff
-$targetUrl = 'http://<hard-coded-public-ip>:8080' . $path; // redacted audited value
+$targetUrl = validated_private_upstream_from_server_env() . $path;
```

```diff
-app.listen(port, '0.0.0.0')
+app.listen(port, process.env.BIND_HOST || '127.0.0.1')
```
Production validation rejects non-loopback `http://` upstreams.

## O. Acceptance criteria

- No bearer/body crosses untrusted cleartext hop.
- Backend direct port is network-restricted.
- Client IP attribution is correct and spoof-resistant.
- UID limiter executes after authentication.

## P. Rollback plan

Restore the prior private proxy transport only; if unavailable, remove service from exposure rather than restore public cleartext.
