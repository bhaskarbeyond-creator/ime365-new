## E. Current implementation

Canonical platform operator mutations require recent SUPER_ADMIN authentication with MFA. `adminUsers` permits role mutation when the actor has either `users.roles.manage` or `users.update`; ADMIN has both. User creation can provision ADMIN, MFA removal accepts `users.update`, and bulk status blocks only self. Bulk Firebase failures are swallowed, database status changes continue, and the UID is reported successful.

## F. Reproduction evidence

Construct the role/action/target matrix from policy grants and route guards. ADMIN satisfies the alternate conditions without the canonical step-up. Inject Firebase update failure in bulk flow: catch suppresses it, subsequent DB mutation and success list still execute.

## G. Expected behavior

Every privileged sink uses one recent-SUPER_ADMIN + MFA + target-hierarchy policy, and identity/database state cannot be reported successful when either side fails.

## H. Root cause analysis

Two active control planes independently implement authorization and mutation choreography → weaker alternate route bypasses canonical policy and hides partial identity failure.

## I. Detailed technical solution

- Inventory every role, MFA, session, create-user and status mutation endpoint.
- Create one `PrivilegedUserService` and one `requirePrivilegedUserMutation(action,target)` guard enforcing SUPER_ADMIN, MFA, fresh auth, protected-last-superadmin and self rules.
- Remove privileged capabilities from broad `users.update`; introduce explicit `users.security.manage` only if business-approved.
- Use a durable saga/outbox for Firebase + MariaDB transitions with reconciliation state; never swallow identity errors.
- Temporarily deny alternate privileged routes until parity is complete.

## J. Proposed patch / code-level repair

```diff
-router.patch('/:uid/role', authenticate, requireAny('users.roles.manage','users.update'), handler)
+router.patch('/:uid/role', authenticate, requireRecentAdminAuthentication,
+  requirePrivilegedTargetHierarchy('role.change'), privilegedUserController.changeRole)
```
Bulk mutation must record per-target `PENDING_IDENTITY`, `PENDING_DATABASE`, `COMPLETED` or `FAILED_RECONCILIATION`, and return non-success for incomplete targets.

**Patch verification:** SOURCE-REVIEWED SECURITY DESIGN; no live Firebase mutation performed.
