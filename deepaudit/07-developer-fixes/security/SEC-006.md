## E. Current implementation

Public liveness/readiness payloads expose commit/identity state, raw DB last errors, authority metrics, host/name/version, encryption, workers and provider posture. Root readiness performs a DB probe outside `/api` limiting.

## F. Reproduction evidence

Request the public endpoints in the isolated runtime. Health/readiness return structured internals; the unavailable DB error was visible in detailed state.

## G. Expected behavior

Public liveness is a stable minimal status. Detailed readiness/metrics require service authentication or network ACL and redact raw topology/errors.

## H. Root cause analysis

Operator diagnostics and load-balancer health were combined in public endpoints → unnecessary information disclosure and probe load.

## I. Detailed technical solution

- Split minimal public `/healthz` and authenticated/internal `/internal/health/details`.
- Return only stable status/code publicly; log correlation IDs rather than raw errors.
- Protect detailed endpoints with mTLS/service auth/network ACL.
- Cache/throttle dependency probes and keep readiness semantics per DB-001.

## J. Proposed patch / code-level repair

```diff
-res.json({ commit, dbHost, dbName, version, lastError, providers, workers, ... })
+res.json({ status: ready ? 'ready' : 'not_ready' })
```
Detailed fields move to an internal authenticated endpoint with redaction.

**Patch verification:** SOURCE/RUNTIME REVIEWED; no production ACL tested.
