## E. Current implementation

`/api/platform` mounts at line 435. Generic admin audit middleware is registered around line 2318, followed by a second identical mount. Express resolves the first router, so the second placement cannot provide the intended generic wrapper. Route/service-level transactional audits still cover multiple operations.

## F. Reproduction evidence

Send a platform route request and instrument middleware order in a disposable branch; the first router handles before the later wrapper. Static order proves the shadow.

## G. Expected behavior

One platform mount occurs at the intended position. Transactional domain audits remain, while generic denied/failed request telemetry is consistently applied.

## H. Root cause analysis

Composition-root merge left duplicate mounts on opposite sides of middleware → the early mount bypasses later generic instrumentation.

## I. Detailed technical solution

- Generate a runtime route/middleware registry.
- Remove the duplicate only after route parity characterization.
- Mount once after authentication/policy/audit wrappers in an intentional order.
- Retain stronger route/service transactional audits; do not replace them with generic logs.
- Test denied, failed and successful operations.

## J. Proposed patch / code-level repair

```diff
-app.use('/api/platform', platformRouter); // early mount
 ... authentication / policy / admin audit middleware ...
 app.use('/api/platform', platformRouter); // single intentional mount
```
