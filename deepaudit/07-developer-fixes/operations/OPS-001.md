# A. OPS-001 — Checked-in PM2 definition resolves to a nonexistent backend entry

## B. Severity

P1 — High. A production deployment that relies on this checked-in definition cannot start the API.

## C. Confirmation status

**CONFIRMED BY SOURCE**

## D. Affected code locations

- [`ecosystem.config.js:16-20`](https://github.com/bhaskarbeyond-creator/ime365-new/blob/df5902dd897ff8e7955a738ac580f2a0d0263d0d/ecosystem.config.js#L16-L20)
- [`backend/package.json:7-10`](https://github.com/bhaskarbeyond-creator/ime365-new/blob/df5902dd897ff8e7955a738ac580f2a0d0263d0d/backend/package.json#L7-L10)
- [`backend/index.js:4260-4268`](https://github.com/bhaskarbeyond-creator/ime365-new/blob/df5902dd897ff8e7955a738ac580f2a0d0263d0d/backend/index.js#L4260-L4268)

## E. Current implementation

The PM2 app uses repository root as `cwd` and `script: 'index.js'`; no root `index.js` exists. The real entry is `backend/index.js`. The environment block also retains stale Firebase-era data-plane settings and points at a missing runbook.

## F. Reproduction evidence

Resolve `path.resolve(config.cwd, config.script)` at the audited tree: it produces `D:\xampp\htdocs\ime365\index.js`, and `Test-Path` is false.

## G. Expected behavior

The checked-in PM2 definition resolves to an existing entry, starts the intended process model, receives externally injected secrets, and passes liveness/readiness before traffic.

## H. Root cause analysis

Deployment metadata was not updated when the backend moved/was consolidated under `backend/` → PM2 targets a missing file → startup failure.

## I. Detailed technical solution

- Choose one supported process mode: direct `backend/index.js` or corrected cluster supervisor after OPS-002.
- Set `cwd`/`script` consistently and document all required environment variable names without values.
- Remove obsolete Firestore-only claims, add graceful shutdown timings, and add post-start health/readiness gates.
- Validate PM2 inherits secrets from the authorized deployment mechanism; absence from the checked file is not proof they are absent in production.

## J. Proposed patch / code-level repair

```diff
 module.exports = { apps: [{
-  cwd: __dirname,
-  script: 'index.js',
+  cwd: path.join(__dirname, 'backend'),
+  script: 'index.js',
   name: 'ime365-backend',
+  wait_ready: true,
+  listen_timeout: 30000,
+  kill_timeout: 15000,
 }] };
```
Add `const path = require('path');` and a staging smoke script that checks `/healthz` then `/readyz`.

**Patch verification:** SOURCE-REVIEWED ONLY; PM2 was not installed/executed during the audit.

## K. Step-by-step developer implementation

1. Decide direct or cluster mode after OPS-002.

1. Document required DB/Firebase/provider variable names in an example/runbook.
1. Start PM2 in staging with production-equivalent secret injection.
1. Assert process stays online, health succeeds, readiness gates schema, reload drains traffic, and rollback works.
