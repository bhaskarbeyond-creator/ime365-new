## E. Current implementation

robots/sitemap publish `ai-resume-builder.local`; the PHP proxy hard-codes an IP; process metadata contains stale assumptions. These values are not derived from one validated deployment configuration.

## F. Reproduction evidence

Inspect the cited files and search for `.local`, raw upstream IPs and obsolete runbook/config values.

## G. Expected behavior

Build/deploy generates canonical public URLs and internal upstream endpoints from validated environment-specific configuration; production packaging rejects placeholders/local hosts.

## H. Root cause analysis

Environment-specific addresses were committed in multiple independent files → drift and invalid production URLs.

## I. Detailed technical solution

- Define a deployment configuration schema with public origin and private API upstream.
- Generate robots/sitemap during build from the validated public origin.
- Configure PHP upstream through server environment outside document root; allow only loopback or HTTPS allowlisted targets.
- Add packaging checks for `.local`, raw public HTTP upstreams and placeholders.

## J. Proposed patch / code-level repair

```diff
-Sitemap: https://ai-resume-builder.local/sitemap.xml
+Sitemap: ${PUBLIC_ORIGIN}/sitemap.xml
```
Generate the final static file in CI; do not serve an unexpanded placeholder.
