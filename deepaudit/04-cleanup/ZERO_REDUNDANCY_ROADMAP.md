# Zero-Redundancy Roadmap

“Zero redundancy” means no unjustified competing authority, not the elimination of deliberate defense-in-depth or adapters.

| Stage | Outcome | Exit criterion |
|---|---|---|
| 1 | Deterministic frontend/backend build | clean rebuild matches manifest |
| 2 | One route registry | no duplicate method/effective-path/owner tuple |
| 3 | One privileged mutation service | every alias passes identical policy matrix |
| 4 | One schema authority | migrations generate snapshot/checksum |
| 5 | Exhaustive repository descriptor | startup/test fails on unclassified method |
| 6 | One template policy/catalog | UI and all exports agree |
| 7 | Clean artifact directory | no unmanifested file shipped |
| 8 | Retired modules removed | full regression and rollback drill pass |

Rarely used functionality remains until usage and ownership evidence supports removal.
